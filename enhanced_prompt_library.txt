PROMPT 9 — Map exposed routes from local source
CATEGORY: Reconnaissance and architecture

From this repository, identify ALL route definitions and HTTP methods. Present as a table: Method | Path | Controller | Auth Required? | Auth Type | Input Params | Middleware. Flag routes that accept user input but lack validation middleware, handle sensitive data without authentication, use different auth patterns than siblings, or accept file uploads. Do not probe a live service or invent routes.

PROMPT 10 — Identify trust boundaries
CATEGORY: Reconnaissance and architecture

Trace where untrusted input crosses into privileged code or sensitive operations. For each trust boundary crossing, document: Source | Input Type | Transformations | Validation Checks | Sink (Sensitive Op) | Missing Controls | Risk Level. Treat each concern as a hypothesis. Prioritize boundaries where user input reaches: database queries, file operations, command execution, template rendering, or external API calls.

PROMPT 11 — Inventory sensitive data
CATEGORY: Reconnaissance and architecture

Identify code paths that read, write, export, or log sensitive data. Categorize by data type: Authentication (passwords, tokens, API keys), Personal (email, name, address), Financial (credit cards, bank accounts), Business (internal pricing, admin configs). For each, document where it enters, how it's stored, where it's logged, who can access it, and what minimization controls exist. Do not print secrets or real user data.

PROMPT 12 — Map roles and permissions
CATEGORY: Reconnaissance and architecture

Extract roles, permissions, ownership checks, and policy helpers from this repository. Create a matrix: Role | Action | Object | Enforcement Point | Evidence. For each cell: ALLOWED (cite code), DENIED (cite code), or UNKNOWN. Highlight any role with UNKNOWN cells for sensitive actions. Mark inconsistencies between roles.

PROMPT 13 — Review API documentation
CATEGORY: Reconnaissance and architecture

Compare the provided API documentation with route/controller code. Create a discrepancy table: Endpoint | Doc Says | Code Does | Type | Security Relevant? Types: UNDOCUMENTED_ENDPOINT, MISSING_AUTH, EXTRA_FIELDS, WRONG_METHOD, DEPRECATED_ACTIVE. Do not assume a mismatch is exploitable.

PROMPT 14 — Find security-sensitive configuration
CATEGORY: Reconnaissance and architecture

Locate security-relevant configuration and present as a posture table: Control | Setting | File | Secure? | Notes. Check for: cookie flags (Secure, HttpOnly, SameSite), CORS origins, CSRF protection, debug mode, trusted proxies, secrets, TLS, CSP, X-Frame-Options, HSTS, rate limits, session timeouts, password policy. Do not expose secret values.

PROMPT 15 — Prioritize attack surfaces
CATEGORY: Reconnaissance and architecture

Rank routes by security relevance. Score each 1-5 for: Data sensitivity, Privilege level, Input complexity, Business impact, Control maturity. Present as a ranked table with total score and recommended investigation order. Explain the evidence behind each score.

PROMPT 16 — Review third-party boundaries
CATEGORY: Reconnaissance and architecture

Identify integrations, webhooks, external API clients, and trust assumptions. For each: Service | Direction | Auth Method | Input Validated? | Secret Storage | Error Handling. Flag hardcoded credentials, missing webhook signatures, unvalidated callbacks, and missing timeouts. Do not contact third parties.

PROMPT 17 — Build an investigation backlog
CATEGORY: Reconnaissance and architecture

Turn the security map into a prioritized backlog. Each item: # | Question | Files/Routes | Priority (H/M/L) | Why | Safe Test Idea | Evidence Needed | Est. Time. Priority = data sensitivity x control weakness x scope confidence. Include time estimates.

PROMPT 18 — Compare two implementations
CATEGORY: Reconnaissance and architecture

Compare two code paths side by side: Aspect | Path A | Path B | Difference | Security Relevant? Check: authorization, input validation, error responses, data exposure, rate limiting, logging, session handling. Explain which differences could lead to a bypass.

PROMPT 19 — Review login flow

PROMPT 86 — Review OAuth implementation
CATEGORY: OAuth, JWT, and token security

Trace the OAuth/OIDC flow: Step | Implementation | Security Control | Concern. Steps: authorization request (state? PKCE?), redirect URI validation (exact match?), code exchange (server-to-server?), token storage (HttpOnly?), refresh (rotation?), scope enforcement, account linking (verified email?). Check for: open redirect via redirect_uri, missing state/PKCE, token leakage, account takeover via linking. Do not test with other users' OAuth accounts.

PROMPT 87 — Review JWT implementation
CATEGORY: OAuth, JWT, and token security

Inspect: Aspect | Implementation | Secure? | Evidence. Aspects: algorithm (explicit whitelist?), secret/key management, claims validation (iss, aud, exp, nbf, iat), storage, revocation, refresh, payload sensitivity. Check for: algorithm confusion (alg:none, RS256→HS256), missing signature verification, expired token acceptance, sensitive data in unencrypted payloads, JWK/kid injection. Do not forge tokens for accounts you don't control.

PROMPT 88 — Review token refresh mechanism
CATEGORY: OAuth, JWT, and token security

Trace: How generated (entropy)? Where stored? Rotated on use? Expiry? Reusable after rotation (replay)? Revoking access also revokes refresh? Bound to client/device? A stolen refresh token can be more damaging than a stolen access token.

PROMPT 89 — Review API key management
CATEGORY: OAuth, JWT, and token security

Inspect: Aspect | Implementation | Secure? Aspects: generation (entropy, prefix), storage (hashed?), rotation, scoping (per-resource?), revocation, transmission (header vs query), logging (masked?). Flag: keys in URLs, keys in client code, overly permissive scopes, missing rotation.

PROMPT 90 — Review OAuth redirect URI handling
CATEGORY: OAuth, JWT, and token security

Inspect: Exact match or pattern? Wildcards/subdomains allowed? Scheme enforced (https)? Fragment/query/path traversal bypass? Malformed/missing URI handling? Per-client or global? Open redirect via redirect_uri is high-severity. Test only with your own registered URIs.

PROMPT 91 — Review SSO integration
CATEGORY: OAuth, JWT, and token security

Trace from IdP to session: Assertion validation (signature, expiry, audience)? Direct login bypass? Account linking by email (verified by IdP?). SSO disable → sessions revoked? Dual SSO + password access? Assertion replay? Check for: replay, unverified email linking, SSO bypass.

PROMPT 92 — Review token scope enforcement
CATEGORY: OAuth, JWT, and token security

Check: Endpoint | Required Scope | Enforced? | Evidence. Common weakness: scopes requested but not checked at use time. Is scope check in middleware (consistent) or per-endpoint (error-prone)? Propose tests with minimal-scope token against privileged endpoints.

PROMPT 93 — Review token revocation
CATEGORY: OAuth, JWT, and token security

Trace: Revocation Event | Access Token | Refresh Token | API Keys | Sessions. Events: password change, admin disable, user revokes app, suspicious activity, expiry. JWTs are problematic for revocation. Identify maximum window where revoked token still works.

PROMPT 94 — Review GraphQL schema and introspection
CATEGORY: GraphQL security

Analyze: Introspection enabled in production? What's exposed (types, queries, mutations, subscriptions)? Admin types visible to regular users? Can introspection be enabled via headers/alternate endpoints? Do not run introspection against production unless authorized.

PROMPT 95 — Review GraphQL authorization
CATEGORY: GraphQL security

Check per resolver: Type.Field | Auth Check | Where Enforced | Concern. Common weakness: auth on query but not nested resolvers (user can query own order, but order.customer resolves ANY customer). Check: missing auth on nested fields, mutations without ownership, subscriptions leaking data.

PROMPT 96 — Review GraphQL query complexity
CATEGORY: GraphQL security

Check: Depth limits? Complexity/cost limits? Deeply nested relationships? Batching in one request? Rate limiting per-query or per-request? Alias duplication of expensive operations? Propose safe test with mildly complex query. Do not overload the server.

PROMPT 97 — Review GraphQL input validation
CATEGORY: GraphQL security

Check: Mutation | Input Type | Scalar Validation | Custom Validation | Concern. Custom scalars (Email, URL, JSON) may not validate correctly. Check for: SQL injection via strings, XSS via returned fields, oversized payloads.

PROMPT 98 — Review GraphQL batching and aliases
CATEGORY: GraphQL security

Check: Batching multiple queries? Aliases calling same query multiple times? Rate limits per-request or per-operation? Can batching bypass auth rate limits (100 login attempts in one request)? Batch size limits? Do not perform high-volume tests.

PROMPT 99 — Review GraphQL error handling
CATEGORY: GraphQL security

PROMPT 109 — Review environment variable usage
CATEGORY: Cloud and infrastructure

Trace: Variable | Purpose | Where Used | Exposed? | Concern. Check: secrets logged or exposed via error pages, debug endpoints dumping env, default values for secrets, variables affecting security (DEBUG=true). Do not expose values.

PROMPT 110 — Review error handling and information disclosure
CATEGORY: Cloud and infrastructure

Trace: Error Type | Response | Logged? | Stack Trace? | Internal Details? Check: stack traces in production, DB errors with table/column names, different error formats (info leakage), version/path disclosure.

PROMPT 111 — Review logging for sensitive data
CATEGORY: Cloud and infrastructure

Inspect: Log Statement | Contains | Masked? | Level | Concern. Check: passwords in login logs, tokens in URL logs, PII in app logs, full request/response in debug, log injection (unsanitized user input).

PROMPT 112 — Review deployment configuration
CATEGORY: Cloud and infrastructure

Check: debug disabled, defaults changed, admin not public, HTTPS enforced, security headers set, errors don't leak, unnecessary services closed, source maps not public, .env/.git/backups not accessible. Base on repository config files.

PROMPT 113 — Review secrets in source code
CATEGORY: Cloud and infrastructure

Search: Pattern | Location | Type | Risk. Patterns: API keys, passwords, tokens, private keys, connection strings, encryption keys, webhook secrets, OAuth secrets. Check .env.example, test fixtures, comments, git history. Report location only, not values.

PROMPT 114 — Review HTTP response headers for cache poisoning
CATEGORY: Cache poisoning and HTTP smuggling

Analyze: Endpoint | Cache-Control | Vary | CDN Cache | Unkeyed Headers | Concern. Check: responses varying by unkeyed headers (X-Forwarded-Host, X-Original-URL), missing Vary, CDN caching authenticated responses.

PROMPT 115 — Review HTTP request handling
CATEGORY: Cache poisoning and HTTP smuggling

Check: Request smuggling (reverse proxy + server disagree on Content-Length vs Transfer-Encoding?), HTTP method override (X-HTTP-Method-Override, _method?), Host header injection (used in URL generation?), Header injection (CRLF in user input?). Base on code and config.

PROMPT 116 — Review CDN and proxy configuration
CATEGORY: Cache poisoning and HTTP smuggling

Check: Client IP determination (X-Forwarded-For, X-Real-IP, CF-Connecting-IP), trusted proxy list correct? X-Forwarded-For injection to bypass IP restrictions? Paths bypassing CDN/WAF (direct origin)? CDN stripping security headers?

PROMPT 117 — Review Content-Type handling
CATEGORY: Cache poisoning and HTTP smuggling

Check: Endpoint | Expected Content-Type | Alternatives Accepted? | Parsing Differences? Endpoints accepting both JSON and form data (enables CSRF), content-type confusion, file uploads trusting Content-Type.

PROMPT 118 — Review Content Security Policy
CATEGORY: Client-side and browser security

Analyze: Directive | Value | Effective? | Bypass Risk. Directives: default-src, script-src, style-src, img-src, connect-src, frame-ancestors, base-uri. Flag: unsafe-inline, unsafe-eval, broad wildcards, CDN user-upload domains, missing base-uri.

PROMPT 119 — Review subdomain security
CATEGORY: Client-side and browser security

Identify: CNAME to decommissioned services (takeover)? Cookie scope sharing? Dev/staging subdomains exposed? Wildcard DNS? Subdomain bypassing same-origin? Do not probe out-of-scope subdomains.

PROMPT 120 — Review postMessage security
CATEGORY: Client-side and browser security

Trace: Sender | Receiver | Origin Check? | Data Validation? | Concern. Check: missing origin validation (accepting any origin), sensitive data without recipient verification, postMessage for auth decisions.

PROMPT 121 — Review client-side storage
CATEGORY: Client-side and browser security

Inspect: Store | Data Type | Sensitive? | Encrypted? | Expiry | XSS Accessible? Stores: localStorage, sessionStorage, non-HttpOnly cookies, IndexedDB. Auth tokens should be in HttpOnly cookies.

PROMPT 122 — Review open redirect vectors
CATEGORY: Client-side and browser security

Search: Endpoint | Parameter | Validation | Bypass Risk | Chain Potential. Check: post-login redirect, OAuth redirect_uri, email confirmation links, error redirects. Open redirect alone is low — document chain potential (OAuth, phishing).
